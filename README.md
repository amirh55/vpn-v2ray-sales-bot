# ربات فروش کانفیگ V2Ray / 3x-ui + پنل مدیریت

ربات تلگرام فروش اشتراک VPN با پنل مدیریت گرافیکی، پرداخت کریپتو و کارت‌به‌کارت با تایید خودکار.

## نصب سریع

روی سرور اوبونتو/دبیان به‌عنوان `root`:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/amirh55/vpn-v2ray-sales-bot/main/scripts/install.sh)
```

همراه با دامنه و HTTPS رایگان:

```bash
DOMAIN=shop.example.com bash <(curl -fsSL https://raw.githubusercontent.com/amirh55/vpn-v2ray-sales-bot/main/scripts/install.sh)
```

در پایان، آدرس پنل و نام کاربری و رمز عبور نمایش داده می‌شود. اگر بعداً آدرس را گم کردید: `vpnshop info`

## آموزش کار با پنل

بعد از نصب، با `vpnshop info` آدرس پنل را بگیرید و وارد شوید. سایدبار پنل این بخش‌ها را دارد:

### ۱. ربات و تنظیمات

| بخش | کارش چیست |
|---|---|
| **تنظیمات اصلی ربات** | توکن ربات، چت آیدی پشتیبانی، نرخ دلار، کارت‌به‌کارت، روش دریافت پیام‌ها، گزارش فروش، متن‌ها |
| **دامنه و SSL** | دامنه پنل، مسیر گواهی SSL، و آدرس‌های Webhook |
| **پشتیبان‌گیری و بازگردانی** | گرفتن فایل zip از همه داده‌ها و برگرداندن آن |
| **پنل‌های 3x-ui** | آدرس و API Token سرورهای V2Ray شما، و خواندن ساختار API هر پنل |

**اولین کارها بعد از نصب:**

۱. **تنظیمات اصلی ربات** → توکن ربات تلگرام را وارد کنید. ربات ظرف چند ثانیه خودکار شروع می‌کند.
۲. در ربات خودتان `/id` را بزنید و عدد را در **چت آیدی پشتیبانی** ثبت کنید تا اعلان پیام‌ها را بگیرید.
۳. **پنل‌های 3x-ui** → سرور V2Ray خود را اضافه کنید.
۴. **سرویس‌ها** → یک سرویس بسازید و Inbound و قالب لینک کانفیگ را تنظیم کنید.
۵. **پلن‌های اشتراک** → قیمت تومانی و دلاری، مدت و حجم را وارد کنید.

### ۲. فروش

| بخش | کارش چیست |
|---|---|
| **سرویس‌ها** | هر سرویس به یک Inbound در 3x-ui وصل است |
| **پلن‌های اشتراک** | قیمت، مدت، حجم و تعداد کاربر |
| **سفارش‌ها/اشتراک‌ها** | همه خریدها، با امکان ارسال دوباره کانفیگ |
| **کدهای تخفیف** | ساخت کد، محدودیت‌ها و دیدن اینکه چه کسی از هر کد استفاده کرده |
| **گزارش فروش** | درآمد، تعداد سفارش، پرفروش‌ترین پلن‌ها و خروجی CSV در هر بازه زمانی |

در **سفارش‌ها** دو کار مفید هست: «ارسال دوباره کانفیگ به کاربر» و «ساخت سرویس در پنل و ارسال» (برای وقتی ساخت کلاینت در 3x-ui شکست خورده).

### ۳. مالی

| بخش | کارش چیست |
|---|---|
| **پرداخت‌ها** | پرداخت‌های کریپتو، با امکان تایید دستی اگر وبهوک نرسیده باشد |
| **تراکنش‌های کیف پول** | تاریخچه شارژ و برداشت |
| **درخواست‌های کارت‌به‌کارت** | فاکتورها و رسیدها، با دکمه تایید دستی |
| **پیامک‌های بانکی** | همه پیامک‌های دریافتی و نتیجه بررسی هرکدام |

### ۴. کاربران و پیام‌رسانی

| بخش | کارش چیست |
|---|---|
| **کاربران تلگرام** | موجودی کیف پول و مسدود کردن کاربر |
| **پیام‌های پشتیبانی** | پیام‌های دریافتی از ربات، و پاسخ دادن به آن‌ها |
| **سوالات متداول** | سوال و جواب‌هایی که در ربات به کاربر نشان داده می‌شود |
| **ارسال پیام گروهی/تکی** | پیام به همه کاربران یا یک Chat ID خاص |

### داشبورد

صفحه اول پنل شش کارت آماری دارد: تعداد کاربران، اشتراک‌های فعال، درآمد ماه، درخواست‌های کارت‌به‌کارت در انتظار، پیام‌های بی‌پاسخ و مجموع کیف‌پول‌ها. زیر آن‌ها دکمه‌ی ورود به **گزارش فروش** قرار دارد.

## 1) نصب روی سرور با یک دستور

روی سرور اوبونتو/دبیان (یا CentOS/Rocky) به‌عنوان `root` فقط همین یک خط را بزنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/amirh55/vpn-v2ray-sales-bot/main/scripts/install.sh)
```

این اسکریپت خودش همه کارها را انجام می‌دهد:

- نصب پیش‌نیازها (python، git، pip)
- پشتیبانی از پایتون ۳.۱۰ تا ۳.۱۴؛ نسخه مناسب Django خودکار انتخاب می‌شود
- دریافت سورس در `/opt/vpnshop` و ساخت محیط مجازی
- ساخت `SECRET_KEY` و یک **مسیر مخفی تصادفی** برای پنل
- اجرای migrate و collectstatic
- ساخت کاربر مدیر با رمز تصادفی و نمایش آن در پایان
- ساخت سرویس‌های systemd برای پنل و ربات با **ری‌استارت خودکار** و بالا آمدن بعد از ریبوت سرور
- نصب دستور مدیریتی `vpnshop`
- باز کردن پورت در فایروال در صورت فعال بودن ufw

در پایان نصب، آدرس پنل و نام کاربری و رمز عبور نمایش داده می‌شود.

### نصب همراه با دامنه و HTTPS رایگان

اگر دامنه دارید و آن را به IP سرور وصل کرده‌اید، به‌جای دستور بالا این را بزنید تا Nginx و گواهی SSL هم خودکار نصب شود:

```bash
DOMAIN=shop.example.com bash <(curl -fsSL https://raw.githubusercontent.com/amirh55/vpn-v2ray-sales-bot/main/scripts/install.sh)
```

این حالت توصیه می‌شود، چون هم پنل روی HTTPS امن می‌شود و هم Webhook درگاه OxaPay بدون HTTPS کار نمی‌کند.

## 1-1) دستور مدیریتی `vpnshop`

بعد از نصب، این دستور روی سرور در دسترس است:

```bash
vpnshop info              # آدرس پنل، کاربران مدیر و وضعیت سرویس‌ها
vpnshop status            # وضعیت کامل سرویس‌ها
vpnshop restart           # ری‌استارت پنل و ربات
vpnshop logs bot          # دیدن زنده لاگ ربات
vpnshop logs web          # دیدن زنده لاگ پنل
vpnshop update            # دریافت آخرین نسخه از گیت‌هاب و ری‌استارت
vpnshop newpath           # ساخت مسیر مخفی جدید برای پنل
vpnshop passwd admin      # تغییر رمز عبور کاربر مدیر
vpnshop adduser           # ساخت کاربر مدیر جدید
vpnshop oxapay            # تست کلید درگاه OxaPay
vpnshop domain            # اعمال دامنه و گواهی SSL روی Nginx
vpnshop webhook           # اعمال حالت Webhook/Polling تلگرام طبق تنظیم پنل
vpnshop webhook status    # نمایش وضعیت فعلی وبهوک در تلگرام
vpnshop reports           # ثبت ارسال خودکار گزارش فروش در cron
vpnshop report daily      # ارسال فوری گزارش امروز برای مدیر
vpnshop backup            # ساخت فایل پشتیبان
vpnshop restore FILE.zip  # بازگردانی از فایل پشتیبان
```

**اگر آدرس پنل را گم کردید**، کافی است روی سرور بزنید:

```bash
vpnshop info
```

## 1-2) مسیر مخفی پنل

پنل مدیریت روی `/admin/` نیست. هنگام نصب یک مسیر تصادفی ۲۰ کاراکتری ساخته می‌شود، مثلا:

```text
https://shop.example.com/k7x2mq9vbn4tz8sw1p3d/
```

به این ترتیب اسکنرهایی که آدرس `/admin/` را تست می‌کنند به صفحه ورود نمی‌رسند و فقط خطای 404 می‌گیرند.

- مسیر فعلی در فایل `/etc/vpnshop/vpnshop.env` با کلید `ADMIN_PATH` ذخیره می‌شود.
- برای عوض کردن مسیر: `vpnshop newpath`
- نکته امنیتی: مسیر مخفی وقتی واقعا ارزش دارد که پنل روی HTTPS باشد، وگرنه آدرس در مسیر شبکه قابل دیدن است. پس حتما نصب با `DOMAIN=` را انجام دهید.

## 2-1) دامنه و گواهی SSL

اگر خودتان روی سرور دامنه و گواهی SSL دارید، لازم نیست فایل‌های سرور را دستی ویرایش کنید. در سایدبار پنل، بخش **دامنه و SSL**:

| فیلد | مقدار نمونه |
|---|---|
| دامنه پنل و ربات | `shop.example.com` (بدون `https://`) |
| آدرس‌ها با https ساخته شوند | روشن |
| مسیر فایل گواهی SSL | `/etc/letsencrypt/live/shop.example.com/fullchain.pem` |
| مسیر فایل کلید خصوصی SSL | `/etc/letsencrypt/live/shop.example.com/privkey.pem` |

بعد از ذخیره، همان‌جا وضعیت را می‌بینید: آدرس فعلی پنل، آدرس Webhook درگاه، و اینکه فایل‌های گواهی موجود و قابل خواندن هستند یا نه (به‌همراه تاریخ انقضای گواهی).

**آدرس‌های Webhook درگاه پرداخت و پیامک بانکی از همین دامنه ساخته می‌شوند**، پس با عوض کردن دامنه همه‌جا به‌روز می‌شود.

### اعمال روی سرور — این مرحله را رد نکنید

⚠️ **ذخیره کردن در پنل به تنهایی کافی نیست.** دامنه باید به فهرست میزبان‌های مجاز Django اضافه شود و تنظیمات Nginx ساخته شود، وگرنه باز کردن پنل با دامنه خطای ۴۰۰ می‌دهد. این کارها نیاز به دسترسی root دارند، پس روی سرور بزنید:

```bash
vpnshop domain
```

این دستور:

- تنظیمات Nginx را در `/etc/nginx/conf.d/vpnshop.conf` می‌سازد
- دامنه را به `ALLOWED_HOSTS` و `PUBLIC_BASE_URL` اضافه می‌کند
- سرویس پنل را ری‌استارت می‌کند تا تنظیم جدید خوانده شود
- اگر Nginx نصب نباشد، خودش نصبش می‌کند

اگر تنظیمات معتبر نباشد، **نسخه قبلی برگردانده می‌شود** تا سایت از کار نیفتد. تا وقتی این دستور اجرا نشود، صفحه دامنه در پنل با پیام قرمز هشدار می‌دهد.

گواهی SSL ندارید؟ روی سرور:

```bash
apt install certbot python3-certbot-nginx && certbot certonly --standalone -d YOUR_DOMAIN
```

برای دیدن تنظیمات بدون اعمال شدن:

```bash
vpnshop domain --print
```

## 3) تنظیم OxaPay

### کدام کلید؟

OxaPay سه نوع کلید دارد و برای ساخت فاکتور فقط یکی از آن‌ها کار می‌کند:

| نوع کلید | کاربرد | محل ساخت |
|---|---|---|
| **Merchant API Key** | ساخت فاکتور و دریافت پرداخت — **همین لازم است** | صفحه Merchant Service |
| General API Key | فقط swap و تبدیل ارز | صفحه Account Settings |
| Payout API Key | فقط واریز به کاربران | صفحه Payout |

اگر General API Key را وارد کنید، ساخت فاکتور با خطای ۴۰۱ رد می‌شود.

### کلیدهای قدیمی

OxaPay دو نسل API دارد و کلیدهایشان با هم سازگار نیستند:

- **API جدید** `api.oxapay.com/v1/payment/invoice` با هدر `merchant_api_key`
- **API قدیمی** `api.oxapay.com/merchants/request` با فیلد `merchant` در بدنه

کلیدهایی که از داشبورد قدیمی گرفته شده‌اند روی API جدید خطای «کلید نامعتبر» می‌دهند، حتی اگر Merchant API Key درستی باشند.

ربات این را خودکار مدیریت می‌کند: اول API جدید را امتحان می‌کند و اگر کلید رد شد، همان درخواست را روی API قدیمی می‌فرستد. پس کلید هر نسلی که باشد کار می‌کند و نیازی به تنظیم ندارید.

### تست کلید

برای اینکه بفهمید کلیدتان درست است یا نه، روی سرور بزنید:

```bash
vpnshop oxapay
```

این دستور با همان کلید ذخیره‌شده یک فاکتور تستی می‌سازد و پاسخ واقعی درگاه را نشان می‌دهد. برای تست یک کلید دیگر بدون ذخیره کردنش:

```bash
vpnshop oxapay --key YOUR_KEY_HERE
```

نکته: حالت sandbox کلید جداگانه ندارد؛ حتی برای تست هم باید Merchant API Key واقعی و معتبر باشد.



درگاه OxaPay از مسیر زیر Webhook می‌گیرد:

```text
https://YOUR_DOMAIN.com/api/payments/oxapay/webhook/
```

در فایل `.env` مقدار `PUBLIC_BASE_URL` را روی دامنه واقعی HTTPS بگذارید:

```env
PUBLIC_BASE_URL=https://YOUR_DOMAIN.com
```

Webhook با HMAC بررسی می‌شود و فقط وضعیت `Paid` باعث شارژ کیف پول و تحویل خودکار می‌شود. وضعیت‌های موقت مثل `Paying` فقط ثبت می‌شوند و تحویل انجام نمی‌شود.

## 4) تنظیم 3x-ui / پنل سنایی

در پنل Django بخش **پنل‌های سنایی / 3x-ui** را بسازید:

- نام پنل
- آدرس پنل، مثل:

```text
https://panel.example.com/YOUR_PANEL_PATH
```

- API Token پنل 3x-ui
- مسیر API پیش‌فرض:

```text
/panel/api
```

### خواندن خودکار ساختار API پنل

نسخه‌های مختلف 3x-ui مسیر و ساختار متفاوتی برای ساخت کلاینت دارند. 3x-ui در نسخه‌های
جدید خودش فهرست کامل این مسیرها را از اینجا می‌دهد:

```text
https://panel.example.com/YOUR_PANEL_PATH/panel/api/openapi.json
```

ربات همین فایل را می‌خواند و درخواست ساخت کلاینت را دقیقاً بر اساس همان می‌سازد،
پس دیگر لازم نیست چند مسیر مختلف را یکی‌یکی امتحان کند.

این کار **خودکار** انجام می‌شود: اولین باری که برای یک پنل سرویس ساخته می‌شود،
ساختار API یک بار خوانده و در همان ردیف پنل ذخیره می‌شود. بعد از آن، هر خرید فقط
یک درخواست به پنل می‌زند.

برای خواندن دستی یا بعد از به‌روزرسانی 3x-ui، در پنل به **پنل‌های سنایی / 3x-ui**
بروید، پنل را تیک بزنید و از منوی «عملیات» گزینه زیر را اجرا کنید:

```text
خواندن ساختار API از پنل (openapi.json)
```

در همان صفحه ویرایش پنل، بخش «ساختار API این پنل» نشان می‌دهد که چند مسیر شناخته
شده و کلاینت از کدام مسیر ساخته می‌شود. ستون **روش API** در فهرست پنل‌ها هم یکی از
این دو را نشان می‌دهد:

| مقدار | یعنی |
|---|---|
| از روی openapi.json | ساختار خوانده شده و درخواست دقیقاً مطابق همین نسخه پنل ساخته می‌شود |
| حدس مسیرهای رایج | این پنل openapi.json نداشت؛ مسیرهای رایج یکی‌یکی امتحان می‌شوند |

اگر پنل شما `openapi.json` ندهد هیچ مشکلی پیش نمی‌آید: روش قبلی به‌عنوان جایگزین
باقی مانده و این مسیرها را امتحان می‌کند:

- `/panel/api/clients/add`
- `/panel/api/clients/bulkCreate`
- `/panel/api/inbounds/addClient`
- `/panel/api/inbound/addClient`

## 5) تعریف سرویس و پلن

### سرویس

در بخش **سرویس‌ها** مشخص کنید:

- نام سرویس، مثل: `VLESS Reality Germany`
- پنل 3x-ui مربوطه
- `Inbound ID`
- قالب لینک کانفیگ
- قالب لینک Subscription

چون ساختار لینک کانفیگ به تنظیمات Inbound شما وابسته است، قالب لینک‌ها قابل تنظیم گذاشته شده‌اند.

متغیرهای قابل استفاده در قالب:

```text
{uuid}
{client_id}
{email}
{inbound_id}
{panel_base_url}
{subscription_base_url}
{service_name}
{plan_name}
{telegram_id}
{duration_days}
{traffic_gb}
{traffic_bytes}
```

مثال قالب Subscription:

```text
https://sub.example.com/sub/{email}
```

مثال قالب کانفیگ، فقط نمونه است و باید با Inbound خودتان تنظیم شود:

```text
vless://{uuid}@your-domain.com:443?type=tcp&security=reality&fp=chrome&sni=google.com#{email}
```

### پلن

در بخش **پلن‌های اشتراک** یا داخل همان سرویس، پلن‌ها را تعریف کنید:

- **قیمت تومانی** — برای کارت‌به‌کارت و کیف پول
- **قیمت دلاری** — برای پرداخت کریپتو
- مدت زمان روز
- حجم گیگابایت؛ عدد `0` یعنی نامحدود
- تعداد کاربر / IP Limit

دو قیمت **کاملاً مستقل** هستند و از هم محاسبه نمی‌شوند. عمداً قیمت دلاری را کمتر بگذارید تا مشتری به پرداخت کریپتو تشویق شود.

مثال:

```text
قیمت تومانی: ۲۵۰,۰۰۰ تومان
قیمت دلاری:  ۳.۵۰ دلار      (با نرخ ۶۰,۰۰۰ یعنی ۲۱۰,۰۰۰ تومان)
```

ربات خودش تخفیف را حساب و به مشتری اعلام می‌کند:

```text
💳 پرداخت ریالی: ۲۵۰,۰۰۰ تومان
🪙 پرداخت کریپتو: ۳.۵۰ دلار

🎁 با پرداخت کریپتو حدود ۱۶٪ ارزان‌تر می‌خرید (حدود ۴۰,۰۰۰ تومان کمتر).
```

اگر قیمت دلاری از تومانی گران‌تر باشد، هیچ تخفیفی نمایش داده نمی‌شود.

نکته: فیلد **نرخ دلار به تومان** در تنظیمات دیگر برای قیمت‌گذاری استفاده نمی‌شود. فقط دو کار می‌کند: تبدیل مبلغ شارژ کیف پول به دلار برای درگاه کریپتو، و محاسبه‌ی درصد تخفیفی که بالا نمایش داده می‌شود. آن را تقریباً به‌روز نگه دارید.

## 6) جریان خرید در ربات

1. کاربر روی **خرید اشتراک جدید** می‌زند.
2. سرویس‌ها و سپس پلن‌ها نمایش داده می‌شوند.
3. بعد از انتخاب پلن، هر دو قیمت به‌همراه میزان تخفیف کریپتو نشان داده می‌شود و کاربر روش پرداخت را انتخاب می‌کند:

| روش | مبلغ | جریان |
|---|---|---|
| 👛 کیف پول | قیمت تومانی | همیشه نمایش داده می‌شود؛ اگر موجودی کم باشد، کسری و گزینه شارژ نشان داده می‌شود |
| 🪙 کریپتو | قیمت دلاری | لینک OxaPay؛ بعد از پرداخت خودکار تحویل |
| 💳 کارت‌به‌کارت | قیمت تومانی + رقم یکتا | شماره کارت نمایش داده می‌شود؛ بعد از تایید پیامک خودکار تحویل |

در همین صفحه دکمه **🎟 کد تخفیف دارم** هم هست. اگر کاربر کد معتبری بزند، هر دو قیمت
با خط خوردگی قیمت قبلی به‌روز می‌شوند و همان قیمت جدید در هر سه روش پرداخت اعمال
می‌شود. توضیح کامل در بخش [کد تخفیف](#6-2-کد-تخفیف).

در هر سه حالت، کلاینت در 3x-ui ساخته و لینک کانفیگ، Subscription و QR Code ارسال می‌شود.

کارت‌به‌کارت فقط وقتی نمایش داده می‌شود که در تنظیمات فعال باشد.

## 6-2) کد تخفیف

این با تخفیف کریپتویی که بالای هر پلن نوشته می‌شود فرق دارد. آن تخفیف خودکار است و
از اختلاف قیمت دلاری و تومانی همان پلن می‌آید. کد تخفیف چیزی است که شما برای یک
کمپین یا برای یک مشتری خاص می‌سازید و او باید آن را تایپ کند.

### ساخت کد

در پنل به بخش **کدهای تخفیف** بروید و «افزودن» را بزنید:

| فیلد | توضیح |
|---|---|
| کد تخفیف | حروف انگلیسی و عدد، بدون فاصله. مثل `NOWRUZ40`. بزرگ و کوچک بودن حروف مهم نیست |
| نوع تخفیف | درصدی، یا مبلغ ثابت تومانی |
| درصد تخفیف | برای نوع درصدی. عدد ۱ تا ۱۰۰ |
| مبلغ تخفیف | برای نوع مبلغ ثابت |
| سقف تخفیف | برای تخفیف درصدی؛ مثلا «۳۰٪ ولی حداکثر ۱۰۰ هزار تومان». ۰ یعنی بدون سقف |
| حداقل مبلغ خرید | کد فقط روی پلن‌های گران‌تر از این مبلغ کار می‌کند. ۰ یعنی محدودیتی ندارد |
| شروع و پایان اعتبار | خالی یعنی بدون محدودیت زمانی |
| حداکثر دفعات استفاده در کل | ظرفیت کل کد. ۰ یعنی نامحدود |
| حداکثر دفعات برای هر کاربر | پیش‌فرض ۱ است، یعنی هر کاربر فقط یک بار. ۰ یعنی نامحدود |
| فقط برای این سرویس‌ها / پلن‌ها | خالی یعنی برای همه. با انتخاب، کد فقط روی همان‌ها کار می‌کند |

### تخفیف روی کدام قیمت اعمال می‌شود

هر پلن دو قیمت مستقل دارد، پس تخفیف روی هر دو جداگانه حساب می‌شود:

- **درصدی:** همان درصد از قیمت تومانی و از قیمت دلاری کم می‌شود.
- **مبلغ ثابت تومانی:** از قیمت تومانی کم می‌شود، و معادل دلاری‌اش با «نرخ دلار به
  تومان» حساب و از قیمت دلاری کم می‌شود.

### چه چیزی جلوی سوءاستفاده را می‌گیرد

- کد به همان پلنی که کاربر در حال دیدنش بوده گره می‌خورد؛ با آن نمی‌تواند به سراغ
  پلن گران‌تری برود.
- محدودیت‌ها دو بار بررسی می‌شوند: یک بار وقتی کاربر کد را می‌زند، و یک بار دیگر
  دقیقاً در لحظه خرید. پس اگر ظرفیت کد بین این دو لحظه تمام شود، نفر دوم آن را
  نمی‌گیرد.
- در خرید کریپتو و کارت‌به‌کارت، سفارش وقتی ساخته می‌شود که پول برسد؛ ممکن است
  ساعت‌ها بعد باشد. کد در آن لحظه دوباره بررسی می‌شود، و اگر منقضی شده باشد خرید با
  قیمت عادی انجام می‌شود و کاربر معطل نمی‌ماند.

### دیدن نتیجه

- در فهرست کدها، ستون «استفاده» نشان می‌دهد از ظرفیت هر کد چقدر مصرف شده است.
- در صفحه ویرایش هر کد، جدول پایین صفحه می‌گوید چه کسی و برای کدام سفارش از آن
  استفاده کرده است.
- در **گزارش فروش** جدولی هست که می‌گوید هر کد چند بار استفاده شده و روی هم چقدر
  تخفیف داده‌اید.
- در فهرست سفارش‌ها هم ستون «کد تخفیف» اضافه شده و می‌توانید بر اساس آن فیلتر کنید.

## 6-1) افزودن اشتراک قدیمی با لینک کانفیگ

کاربرانی که کانفیگشان را از جای دیگری تهیه کرده‌اند هم می‌توانند حجم و زمان باقی‌مانده را داخل ربات ببینند.

1. کاربر روی **➕ افزودن اشتراک قدیمی** می‌زند.
2. ربات می‌گوید: «لینک کانفیگ خود را ارسال نمایید».
3. کاربر لینک را می‌فرستد. ربات شناسه کلاینت را از لینک بیرون می‌کشد:
   - `vless://` و `vmess://` → فیلد `id` (همان UUID)
   - `trojan://` و `ss://` → فیلد `password`
   - ارسال UUID خالی هم پذیرفته می‌شود.
4. ربات همه پنل‌های **فعال** را می‌گردد و کلاینتی با همان شناسه را پیدا می‌کند.
5. اگر پیدا شد، سرویس به حساب کاربر اضافه می‌شود و مصرف نمایش داده می‌شود.

نکته: مچ کردن بر اساس شناسه لینک انجام می‌شود، نه نام یا remark، چون remark در پنل قابل تغییر است.

مصرف هیچ‌وقت در دیتابیس ذخیره نمی‌شود و هر بار زنده از پنل خوانده می‌شود. کاربر با دکمه **🔄 بروزرسانی** می‌تواند دوباره بخواند.

نمونه پیامی که کاربر می‌بیند:

```text
📊 Germany Node

حجم کل: ۵۰.۰۰ گیگابایت
مصرف‌شده: ۱۱.۰۰ گیگابایت (۲۲٪)
باقی‌مانده: ۳۹.۰۰ گیگابایت
انقضا: ۲۰۲۶-۰۹-۰۲ (۲۹ روز باقی‌مانده)
```

سرویس‌های افزوده‌شده در پنل مدیریت، بخش **سرویس‌های افزوده‌شده کاربران** قابل مشاهده‌اند.

## 6-2) شارژ کیف پول

شارژ در دو مرحله انجام می‌شود:

۱. کاربر مبلغ را انتخاب می‌کند: ۱۰۰ هزار، ۵۰۰ هزار، ۱ میلیون، ۲ میلیون یا **مبلغ دلخواه**
۲. سپس روش پرداخت را انتخاب می‌کند: **کریپتو** یا **کارت‌به‌کارت**

مبلغ دلخواه هم دقیقاً به همان صفحه انتخاب روش پرداخت می‌رسد.

کارت‌به‌کارت فقط وقتی در این لیست دیده می‌شود که در تنظیمات فعال باشد.

## 6-3) سوالات و راهنمایی

بخشی که خودتان محتوایش را می‌نویسید؛ مثلاً آموزش پرداخت با کریپتو.

کاربر روی **❓ سوالات و راهنمایی** می‌زند، یک پیام معرفی می‌بیند و سوال‌ها زیرش به صورت دکمه هستند. با کلیک روی هر سوال، پاسخش نمایش داده می‌شود و دکمه بازگشت به لیست سوالات دارد.

### افزودن سوال

در پنل، بخش **سوالات متداول**:

- **سوال** روی دکمه نمایش داده می‌شود، پس کوتاه بنویسید (حداکثر ۱۰۰ کاراکتر)
- **پاسخ** می‌تواند طولانی باشد و از تگ‌های `<b>` و `<code>` و لینک پشتیبانی می‌کند
- **ترتیب نمایش** جای سوال در لیست را مشخص می‌کند
- با غیرفعال کردن، سوال بدون حذف شدن از ربات پنهان می‌شود

متن معرفی بالای لیست در **تنظیمات اصلی ربات** → «متن بالای بخش سوالات متداول» قابل تغییر است.

این بخش وقتی فروشگاه موقتاً غیرفعال باشد هم در دسترس می‌ماند، چون کاربر ممکن است همان موقع به راهنمایی نیاز داشته باشد.

## 7) ارتباط با ما و اعلان پیام‌ها

کاربر پیام را داخل ربات ارسال می‌کند و ربات **بلافاصله در تلگرام به شما اعلان می‌دهد** تا نیازی به چک کردن پنل نباشد.

اعلان شامل نام، Username، Chat ID و متن پیام است. اگر کاربر عکس فرستاده باشد، عکس هم برای شما ارسال می‌شود.

### راه‌اندازی اعلان

۱. در ربات خودتان دستور `/id` را بزنید. ربات شناسه چت شما را می‌دهد.
۲. آن عدد را در پنل، **تنظیمات اصلی ربات** → **چت آیدی پشتیبانی** ثبت کنید.

اگر می‌خواهید اعلان به دو نفر برسد، عدد دوم را در **چت آیدی مدیر برای اعلان‌ها** بگذارید. اگر هر دو یکی باشند، پیام تکراری ارسال نمی‌شود.

اعلان‌ها برای رسید کارت‌به‌کارت هم ارسال می‌شود.

### اگر اعلان نمی‌رسد

اگر هیچ‌کدام از دو فیلد پر نشده باشد یا شناسه اشتباه باشد، دلیلش در لاگ ربات نوشته می‌شود:

```bash
vpnshop logs bot
```

نکته: باید حداقل یک بار خودتان به ربات `/start` زده باشید، وگرنه تلگرام اجازه ارسال پیام به شما را نمی‌دهد.

اطلاعات مدیر یا پشتیبانی هیچ‌وقت به کاربر نمایش داده نمی‌شود.

## 8) ارسال پیام به کاربران

در بخش **ارسال پیام گروهی/تکی** فقط دو چیز را پر می‌کنید:

| فیلد | توضیح |
|---|---|
| گیرنده | خالی بگذارید تا برای همه کاربران ربات برود. برای ارسال به یک نفر، Chat ID او را بنویسید |
| متن پیام | می‌توانید از `<b>` و `<code>` و لینک استفاده کنید |

بعد **ذخیره** را بزنید. همین. پیام همان لحظه ارسال می‌شود و بالای صفحه به شما
می‌گوید برای چند نفر رفت.

بقیه‌ی فیلدها (وضعیت، تعداد موفق، تعداد ناموفق، آخرین خطا) دیگر قابل تغییر
نیستند و فقط یک **گزارش** از نتیجه‌ی ارسال هستند. اگر پیامی به کسی نرسد، دلیلش
همان‌جا در «نتیجه ارسال» نوشته می‌شود — معمولاً یعنی آن کاربر ربات را بلاک کرده است.

- اگر گیرنده یک نفر باشد یا کاربران کم باشند، ارسال همان لحظه تمام می‌شود.
- برای تعداد زیاد، ارسال در پس‌زمینه ادامه پیدا می‌کند؛ کمی بعد همان صفحه را باز
  کنید تا تعداد نهایی را ببینید.
- اگر ارسال ناموفق بود، از فهرست پیام‌ها اکشن **📨 ارسال دوباره این پیام‌ها** را بزنید.
- متن یک پیامِ ارسال‌شده دیگر قابل ویرایش نیست، تا گزارش با چیزی که واقعاً برای
  مشتری رفته یکی بماند.

## 8-2) پاسخ دادن به پیام پشتیبانی

وقتی کاربر از «☎️ ارتباط با ما» پیامی می‌فرستد، اعلانش برای شما می‌آید و خود پیام
در بخش **پیام‌های پشتیبانی** ذخیره می‌شود.

برای پاسخ دادن:

۱. در پنل به **پیام‌های پشتیبانی** بروید و روی پیام کلیک کنید.
۲. متن کاربر بالای صفحه است. در کادر **پاسخ شما به کاربر** جواب را بنویسید.
۳. **ذخیره** را بزنید — پاسخ همان لحظه در تلگرام برای کاربر ارسال می‌شود.

بعد از ارسال، ستون «پاسخ» در فهرست تیک می‌خورد و زمان ارسال ثبت می‌شود. اگر ارسال
نشود (مثلاً کاربر ربات را بلاک کرده)، پیام خطا را می‌بینید و آن پیام **پاسخ‌داده‌شده
علامت نمی‌خورد**، تا از قلم نیفتد.

## 8-1) گزارش فروش روزانه و ماهانه

از سایدبار، بخش **فروش → گزارش فروش**. یک دکمه هم بالای داشبورد اصلی هست.

### بازه گزارش

بالای صفحه دکمه‌های آماده هست: **امروز، دیروز، ۷ روز، ماه جاری شمسی، ماه قبل، ۱۲ ماه**.
اسم دو دکمه‌ی ماه، خودِ نام ماه شمسی است (مثل «مرداد ۱۴۰۵» و «تیر ۱۴۰۵»).

**«این ماه» یعنی ماه شمسی، نه میلادی.** یعنی «مرداد» از اول مرداد تا آخر مرداد
حساب می‌شود، نه از اول August.

اگر بازه دلخواه می‌خواهید، دو تاریخ «از» و «تا» را انتخاب و «نمایش» را بزنید.
انتخابگر تاریخ همان تقویم خود مرورگر است (میلادی)، ولی معادل شمسی هر تاریخ
درست زیر همان کادر نوشته می‌شود و بقیه‌ی صفحه کاملاً شمسی است.

### چه چیزی نشان می‌دهد

کارت‌های بالای صفحه:

| کارت | یعنی |
|---|---|
| درآمد فروش | مجموع مبلغی که واقعا از سفارش‌های این بازه گرفته‌اید. اگر تخفیفی داده باشید، مبلغ قبل از تخفیف هم زیرش نوشته می‌شود |
| تعداد سفارش | تعداد سفارش‌ها، به‌همراه میانگین مبلغ هر سفارش |
| تخفیف داده‌شده | مجموع تخفیفی که کدها روی این بازه ایجاد کرده‌اند |
| کاربر جدید | کاربرانی که در این بازه اولین بار ربات را باز کرده‌اند |
| شارژ کیف پول | مجموع پرداخت‌های تاییدشده. این با درآمد فرق دارد؛ پول در کیف پول تا وقتی خرج نشده فروش حساب نمی‌شود |
| منقضی تا ۷ روز آینده | تعداد اشتراک‌هایی که به‌زودی تمام می‌شوند — فهرست کسانی که باید سراغشان بروید |

پایین‌تر، چهار جدول: **روش پرداخت، سرویس، پلن، و کدهای تخفیف**؛ و در آخر جدول
**فروش روزانه** با نوار مقایسه‌ای، تا ببینید کدام روزها بهتر بوده‌اند.

### خروجی CSV

دکمه **خروجی CSV** همان بازه انتخاب‌شده را به شکل فایل می‌دهد. فایل با کدگذاری
مناسب اکسل ساخته می‌شود، پس متن فارسی درست باز می‌شود. جدول فروش روزانه در فایل
هم تاریخ شمسی دارد و هم میلادی، چون اکسل فقط روی میلادی می‌تواند مرتب‌سازی کند.

### ارسال خودکار به تلگرام

۱. در **تنظیمات اصلی ربات → گزارش فروش**، گزینه «ارسال گزارش فروش به مدیر» را روشن
   کنید و ساعت ارسال را انتخاب کنید (عدد ۰ تا ۲۳ به وقت سرور).

۲. مطمئن شوید «چت آیدی مدیر» پر است. اگر نمی‌دانید چیست، در ربات `/id` بزنید.

۳. یک بار روی سرور این را اجرا کنید تا در cron ثبت شود:

```bash
vpnshop reports
```

بعد از آن:

- **هر شب** در ساعتی که انتخاب کرده‌اید، خلاصه فروش همان روز فرستاده می‌شود.
- **اول هر ماه** در همان ساعت، به‌جای گزارش روزانه، گزارش کامل ماه گذشته می‌آید.

برای دیدن نمونه‌اش همین حالا، بدون منتظر ماندن:

```bash
vpnshop report daily
vpnshop report monthly
```

## 9) کارت‌به‌کارت با تایید خودکار

کارت‌به‌کارت به صورت پیش‌فرض غیرفعال است.

### چطور کار می‌کند

هر فاکتور یک **مبلغ دقیق و یکتا** می‌گیرد: قیمت + یک عدد تصادفی بین ۱۰ تا ۹۹۰ تومان.

```text
قیمت سرویس: ۲۵۰٬۰۰۰ تومان
مبلغ واریز:  ۲۵۰٬۴۷۰ تومان   ← فقط برای این سفارش
```

چون هیچ دو فاکتور بازی مبلغ یکسان ندارند، وقتی پیامک بانکی می‌رسد ربات دقیقاً می‌داند کدام سفارش پرداخت شده و خودکار کیف پول را شارژ می‌کند.

فاکتور به‌صورت پیش‌فرض **۳۰ دقیقه** اعتبار دارد (قابل تنظیم).

### راه‌اندازی

۱. در **تنظیمات اصلی ربات**، بخش کارت‌به‌کارت:
   - «پرداخت کارت‌به‌کارت فعال باشد» را روشن کنید
   - **شماره کارت**، **نام صاحب کارت** و **نام بانک** را وارد کنید
   - در بخش «تایید خودکار با پیامک بانکی»، آن را روشن کنید
   - **شماره‌های مجاز بانک** را وارد کنید، مثل `200080,7575`

شماره کارت به کاربر در قالب قابل کپی نمایش داده می‌شود؛ با یک لمس کپی می‌شود. مبلغ دقیق هم قابل کپی است.

۲. ذخیره کنید. حالا در همان صفحه، فیلد **آدرس وبهوک پیامک** را می‌بینید:

```text
https://YOUR_DOMAIN.com/api/payments/sms/webhook/?secret=XXXXXXXX
```

کلید مخفی خودکار ساخته می‌شود. اگر خواستید عوضش کنید، فیلد را خالی کنید و ذخیره کنید تا کلید جدید بسازد.

۳. روی گوشی‌ای که پیامک بانک را می‌گیرد، اپ فوروارد پیامک را نصب کنید و همان آدرس را واردش کنید.

**اپ اختصاصی همین پروژه** در پوشه `android-sms-forwarder/` قرار دارد و راهنمای کاملش اینجاست:
[android-sms-forwarder/README_FA.md](android-sms-forwarder/README_FA.md)

چون سورسش داخل همین ریپو است، برخلاف اپ‌های ناشناس می‌دانید چه چیزی پیامک‌های بانکی‌تان را می‌خواند. APK را گیت‌هاب خودش می‌سازد و لازم نیست Android Studio نصب کنید.

اگر ترجیح می‌دهید از اپ آماده استفاده کنید، هر اپ SMS Forwarder دیگری هم کار می‌کند؛ فقط باید بتواند POST با فرمت زیر بفرستد.

### فرمت پیامی که اپ باید بفرستد

`POST` با یکی از این سه فرمت — هر سه پذیرفته می‌شوند:

```json
{"from": "200080", "text": "متن کامل پیامک بانک"}
```

- JSON با کلیدهای `text` یا `message` یا `msg` یا `body` یا `content` برای متن، و `from` یا `sender` یا `number` یا `address` برای شماره فرستنده
- فرم‌انکد با همان نام‌ها
- کوئری‌استرینگ با همان نام‌ها

کلید مخفی را می‌توانید در URL (`?secret=`) یا در هدر `X-Secret` بفرستید.

### تست وبهوک

```bash
curl -X POST "https://YOUR_DOMAIN.com/api/payments/sms/webhook/?secret=YOUR_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"from":"200080","text":"واریز: 2,504,700 ریال"}'
```

پاسخ `{"ok":true,"matched":false,...}` یعنی وبهوک سالم است ولی فاکتور بازی با آن مبلغ نبود.

### نکات مهم

- پیامک بانک‌های ایرانی معمولاً به **ریال** است. ربات هر دو حالت ریال و تومان را بررسی می‌کند.
- فقط پیامک‌های **واریز** پذیرفته می‌شوند. پیامک برداشت یا خرید نادیده گرفته می‌شود.
- عدد «مانده حساب» به‌عنوان مبلغ واریز در نظر گرفته نمی‌شود.
- یک پیامک تکراری باعث شارژ دوباره نمی‌شود.
- همه پیامک‌های دریافتی در بخش **پیامک‌های بانکی** پنل ذخیره می‌شوند، حتی آن‌هایی که به فاکتوری نخوردند. برای پیدا کردن واریزی‌های بدون فاکتور مفید است.

### رسید و تایید دستی

کاربر بعد از واریز، عکس رسید یا شماره پیگیری را در ربات می‌فرستد. این رسید همیشه ثبت و برای پشتیبانی ارسال می‌شود — چه پرداخت خودکار تایید شده باشد چه نه.

اگر مهلت فاکتور تمام شده باشد یا پیامک نرسیده باشد، مدیر از بخش **درخواست‌های کارت‌به‌کارت** با اکشن «تایید و شارژ کیف پول» می‌تواند دستی تایید کند. تایید دستی روی فاکتورهای منقضی هم کار می‌کند.

**اگر فاکتور مربوط به خرید یک پلن بوده باشد، با همین تایید دستی سرویس ساخته و کانفیگ بلافاصله برای کاربر ارسال می‌شود.**

## 9-2) تایید دستی و ارسال کانفیگ از پنل

سه اکشن برای وقتی که تایید خودکار انجام نشده:

| کجا | اکشن | چه می‌کند |
|---|---|---|
| درخواست‌های کارت‌به‌کارت | تایید و شارژ کیف پول | کیف پول را شارژ می‌کند و اگر پلنی در انتظار بوده، سرویس را می‌سازد و کانفیگ را می‌فرستد |
| پرداخت‌ها | تایید دستی پرداخت، شارژ کیف پول و تحویل سرویس | برای وقتی که پرداخت کریپتو انجام شده ولی وبهوک درگاه نرسیده |
| سفارش‌ها | ارسال دوباره کانفیگ به کاربر | کانفیگ و QR یک سفارش موجود را دوباره می‌فرستد |
| سفارش‌ها | ساخت سرویس در پنل و ارسال | برای سفارشی که پرداختش انجام شده ولی ساخت کلاینت در 3x-ui شکست خورده |

هر چهار اکشن در برابر اجرای دوباره امن هستند: پرداختی که یک بار تایید شده، دوباره کیف پول را شارژ نمی‌کند.

## 9-1) پشتیبان‌گیری و بازگردانی

### از داخل پنل

در سایدبار، بخش **پشتیبان‌گیری و بازگردانی**:

- **دانلود فایل پشتیبان** — یک فایل zip شامل همه داده‌ها و فایل‌های آپلودشده
- **بازگردانی** — همان فایل zip را آپلود کنید

### از روی سرور

```bash
vpnshop backup                        # ساخت فایل در /var/lib/vpnshop/backups
vpnshop restore /path/to/backup.zip   # بازگردانی و ری‌استارت خودکار سرویس‌ها
```

برای گرفتن پشتیبان خودکار هر شب، این خط را به crontab اضافه کنید:

```bash
0 3 * * * /usr/local/bin/vpnshop backup >/dev/null 2>&1
```

### چه چیزی داخل فایل است

- همه جدول‌ها: تنظیمات، پنل‌های 3x-ui، سرویس‌ها، پلن‌ها، کاربران تلگرام، سفارش‌ها، تراکنش‌ها، پرداخت‌ها، پیام‌های پشتیبانی، سرویس‌های افزوده‌شده
- حساب‌های مدیر پنل
- فایل‌های آپلودشده مثل QR کدها

داده‌ها به صورت JSON ذخیره می‌شوند نه کپی فایل SQLite، بنابراین پشتیبانی که روی SQLite گرفته‌اید روی PostgreSQL هم قابل بازگردانی است.

### نکات مهم

⚠️ **فایل پشتیبان شامل توکن ربات، کلید درگاه پرداخت و اطلاعات کاربران است.** جای امن نگه دارید و برای کسی نفرستید.

- بازگردانی رکوردهایی با شناسه یکسان را بازنویسی می‌کند و بقیه را دست‌نخورده می‌گذارد. روی یک نصب تازه، نتیجه یک کپی کامل است.
- قبل از بازگردانی، یک پشتیبان از وضعیت فعلی بگیرید.
- بعد از بازگردانی از داخل پنل، حتماً `vpnshop restart` را بزنید. نسخه خط فرمان خودش این کار را می‌کند.

## 10) اجرای دائمی روی سرور

اگر با اسکریپت نصب (بخش ۱) نصب کرده باشید، این کار **خودکار انجام شده است**. دو سرویس systemd ساخته می‌شود:

- `vpnshop-web` : پنل مدیریت با gunicorn
- `vpnshop-bot` : ربات تلگرام

هر دو با `Restart=always` اجرا می‌شوند، یعنی اگر کرش کنند خودکار بالا می‌آیند و بعد از ریبوت سرور هم خودشان روشن می‌شوند.

```bash
vpnshop status      # وضعیت
vpnshop restart     # ری‌استارت
vpnshop logs        # لاگ زنده هر دو سرویس
```

یا مستقیم با systemd:

```bash
systemctl status vpnshop-web vpnshop-bot
journalctl -u vpnshop-bot -f
```

### به‌روزرسانی به آخرین نسخه

```bash
vpnshop update
```

این دستور آخرین تغییرات را از گیت‌هاب می‌گیرد، کتابخانه‌ها را نصب می‌کند، migrate و collectstatic می‌زند و سرویس‌ها را ری‌استارت می‌کند.

## 10-1) نسخه پایتون و وابستگی‌ها

کاری لازم نیست؛ فقط اسکریپت نصب را اجرا کنید. اگر پایتون سرور خارج از این محدوده باشد، اسکریپت تلاش می‌کند یک نسخه سازگار نصب کند و اگر نشد پیام واضح می‌دهد.

## 10-2) Webhook تلگرام به جای Polling

دو راه برای اینکه ربات پیام‌های تلگرام را بگیرد وجود دارد. حالت پیش‌فرض **Polling**
است و روی هر سروری کار می‌کند؛ **Webhook** سریع‌تر و سبک‌تر است ولی دامنه می‌خواهد.

| | Polling (پیش‌فرض) | Webhook |
|---|---|---|
| چطور کار می‌کند | ربات مدام از تلگرام می‌پرسد «پیام جدیدی هست؟» | تلگرام خودش پیام‌ها را به سرور شما می‌فرستد |
| نیاز به دامنه و SSL | ندارد | **دارد** — تلگرام وبهوک بدون HTTPS را قبول نمی‌کند |
| سرعت پاسخ | تا چند ثانیه تاخیر | تقریبا بدون تاخیر |
| مصرف سرور | یک پروسه جداگانه همیشه روشن | بدون پروسه اضافه؛ همان وب‌سرور پنل جواب می‌دهد |

### روشن کردن Webhook

**پیش‌نیاز:** ابتدا [دامنه و گواهی SSL](#2-1-دامنه-و-گواهی-ssl) را تنظیم کرده و
`vpnshop domain` را زده باشید. بدون آن، وبهوک کار نمی‌کند.

۱. در پنل، **تنظیمات اصلی ربات → روش دریافت پیام‌های تلگرام**، گزینه
   «دریافت پیام‌ها با Webhook به‌جای Polling» را روشن و ذخیره کنید.

۲. روی سرور بزنید:

```bash
vpnshop webhook
```

همین دستور وبهوک را در تلگرام ثبت و سرویس‌ها را ری‌استارت می‌کند. اگر دسترسی به
سرور ندارید، در همان صفحه تنظیمات لینک‌های «ثبت وبهوک» و «بررسی وضعیت» هم هست.

۳. برای اطمینان:

```bash
vpnshop webhook status
```

### برگشتن به Polling

همان گزینه را در پنل خاموش کنید و دوباره `vpnshop webhook` را بزنید. وبهوک از
تلگرام حذف می‌شود و سرویس ربات دوباره Polling را شروع می‌کند.

### نکات

- **هیچ‌وقت هر دو حالت هم‌زمان کار نمی‌کنند.** تلگرام تا وقتی وبهوکی ثبت باشد اجازه
  Polling نمی‌دهد. برای همین سرویس ربات در حالت وبهوک بیکار می‌ماند و کاری نمی‌کند
  تا اگر دوباره Polling را روشن کردید، خودش شروع کند.
- آدرس وبهوک یک کلید مخفی تصادفی در خودش دارد و تلگرام هم یک هدر امنیتی می‌فرستد.
  هر درخواستی که هر دو را نداشته باشد با ۴۰۳ رد می‌شود.
- این آدرس را جایی منتشر نکنید. اگر لو رفت، فیلد «کلید مخفی وبهوک تلگرام» را در
  پنل خالی کنید و ذخیره بزنید تا کلید جدید ساخته شود، بعد دوباره
  `vpnshop webhook` را اجرا کنید.
- بعد از هر بار عوض کردن دامنه، `vpnshop webhook` را دوباره بزنید تا آدرس جدید در
  تلگرام ثبت شود.

## 11) نکات امنیتی مهم

- از HTTPS استفاده کنید؛ OxaPay برای Webhook روی localhost کار عملیاتی ندارد. ساده‌ترین راه، نصب با `DOMAIN=` است.
- آدرس پنل روی یک مسیر مخفی تصادفی است، ولی این جایگزین رمز قوی نیست. حتما رمز کاربر مدیر را عوض کنید: `vpnshop passwd admin`
- اگر فکر می‌کنید مسیر پنل لو رفته: `vpnshop newpath`
- `SECRET_KEY` و API Token ها را عمومی نکنید. همه در `/etc/vpnshop/vpnshop.env` با دسترسی `600` ذخیره می‌شوند.
- فایل دیتابیس SQLite برای شروع مناسب است؛ برای فروش واقعی بهتر است PostgreSQL استفاده شود.
- سرویس‌ها با کاربر root اجرا می‌شوند تا نصب ساده بماند. اگر حساسیت امنیتی بالایی دارید، سرور را فقط برای همین پنل استفاده کنید و دسترسی SSH را محدود کنید.
- در صورت فعال کردن کارت‌به‌کارت، هر متنی که در `card_to_card_text` بنویسید به کاربر نمایش داده می‌شود.
- استفاده از VPN/V2Ray باید مطابق قوانین محل فعالیت شما باشد.
